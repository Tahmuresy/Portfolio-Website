Intent-Preserving Completion of Non-Expert Sketches into Neoplastic Compositions

Tahmures Ghiyasi · October 2026

A person with no painting experience draws a few rough strokes; the system must return a finished composition that obeys Mondrian's rules and still feels like theirs. This report describes a learned stroke recogniser validated on real human drawings, a structured translation of strokes into neoplastic constraints, and a completion objective that trades harmony against fidelity under a single user control — all running in the browser, and designed as the perception-and-planning layer for a human–robot painting system.

1. Problem

A non-expert draws a few rough strokes; the system must return a finished composition that (a) obeys neoplastic rules — only horizontals and verticals, primary colours and non-colours, balanced asymmetry — and (b) is recognisably theirs. These pull against each other: every correction that improves harmony erodes authorship. v1 handled this with one heuristic (bounding-box aspect ≥ 2.2 → line, else colour plane). It could not tell a box from a smudge, an L from a diagonal, or a re-traced line from two lines.

Contributions of v2

  1. A learned gesture recogniser (line / path / outline / fill / dot) trained on a synthetic non-expert noise model and validated on real human strokes (Google Quick, Draw!), with a dev/test protocol that keeps the test split untouched.
  2. Structured geometric decoding into neoplastic constraints, including an explicit, art-historically motivated treatment of diagonals.
  3. A fidelity-aware completion objective that trades harmony against faithfulness under one user-facing control (Correction), plus two generator fixes found during evaluation: budget conditioning and a near-miss penalty.
  4. A transparent, correctable interface: every mark shows its reading and confidence, and the user can override it with one tap. Each override is also a labelled example for future training.

2. Pipeline

stroke ─► capture (4-unit motion threshold) ─► finalize (RDP ε=1.5, ≤96 pts)
       ─► 16 features ─► MLP 16-24-5 ─► class + confidence   (user override wins)
       ─► decode: line/path → ShortStraw corners → TLS fit per segment → axis snap (±25°)
                  diagonal → orthogonal step;  outline → 4 cuts on robust bbox
                  fill / colour stroke → region;  dot → plane pin
all marks ─► consolidate: merge re-traces · align collinear segments · snap ends to
             perpendicular lines/edges · absorb edge-huggers · snap regions to lines
         ─► completion: N candidates, forced cuts first (budget-conditioned),
             proposal mixture for regions, select argmin  D_harmony + λ(c)·L_fidelity

The interpreter (interpreter.js) is a single source file used by both the training pipeline and the web app. build.js inlines it into the page, so the features the model was trained on are byte-identical to the ones computed in the browser.

3. Features

All features are scale-invariant except log_size, which is needed to detect dots. Strokes are resampled to 64 equidistant points.

# Feature Captures
1 log(bbox diagonal / canvas diagonal) absolute size (dots)
2 log(path length / bbox diagonal) ink per extent (fills ≫ lines)
3–4 endpoint gap / length, / diagonal closure (outlines)
5 bbox aspect elongation
6–7 TLS residual / diagonal; √(λ₂/λ₁) straightness
8–9 Σ|turning|/2π; |Σ turning|/2π wiggle vs. winding
10 ShortStraw interior corners paths
11 direction reversals along major axis overlapping passes (hatching)
12 6×6 occupancy of bbox coverage
13 convex-hull area / diagonal² enclosed area
14 max chord deviation / diagonal bow
15 self-intersections scribbles
16 direction reversals along minor axis oscillation while progressing (zigzag) — added after dev-split error analysis (§5)

4. Data

Synthetic training data (synth.js): 3,000 strokes per class plus 600 per class for validation, on a 1000-unit canvas. The generator covers lines (75% near an axis), L-corners, steps, zigzags, arcs, waves, rectangles drawn from any start point with rounded corners and closure gaps or overshoot, ellipses, triangles, hatching, random-walk and looping scribbles, taps and micro-squiggles. The noise model includes low-frequency perpendicular wobble, Gaussian jitter, pen-down/pen-up hooks, sag, small rotations and sampling dropout. Every stroke then goes through the app's exact capture pipeline. A shift set raises tremor 1.4–2.4×, dropout and rotation to test robustness.

Real data (fetch_quickdraw.js): recognised, single-stroke drawings from Quick, Draw! (CC BY 4.0). Mapping: line → line, zigzag → path, circle / square / triangle → outline. That gives 1,800 strokes, split by index into dev (900) and test (900). Drawings are randomly scaled and placed, then passed through the app's capture pipeline.

Protocol. All error analysis and the one model revision were done on dev only. Test was evaluated once, after the final model was fixed.

Accuracy %, with 95% bootstrap CI (2,000 resamples). Full tables and confusion matrices: results/results.md.

MLP, gen v2, 16 features (final) 99.6 97.6 94.4 96.4 [95.1, 97.6]
  • Sim-to-real gap and fix. Before the revision, the model scored 99% on synthetic data but only 88% on real dev strokes. Almost all of the gap was real zigzags read as fill (dev zigzag accuracy 68%). Inspecting dev showed two causes. First, real zigzags are much less elongated than the generator's (median aspect 0.62 vs ≤ 0.45). Second, the oscillation feature only measured the major axis. Widening the zigzag distribution and adding feature 16 raised held-out test zigzag accuracy from 73.3% to 92.0%, and overall real-test accuracy from 90.0% to 96.4%. The confidence intervals do not overlap.
  • Features carry most of the signal. Softmax regression on the same 16 features reaches 95.2% on real test. The MLP's gain over it is small. We keep the MLP because it is better on every split and its weights are only 4.7 KB.
  • Geometry. For synthetic lines drawn with horizontal or vertical intent (n = 818), the full pipeline picks the correct axis 100% of the time. Median position error is 0.3 units and p90 is 1.1 units on a 1000-unit canvas.
  • Completion fixes found during evaluation.
  • Near-miss jogs: 229 of 500 compositions from the original generator contained parallel lines that nearly, but not exactly, align across a perpendicular — an arrangement Mondrian avoided. A penalty in the harmony score reduces this to 1 of 500.
  • Budget conditioning: previously, every block created by a human line restarted the Mondrian process with the full budget, so many marks produced clutter. Each forced cut now consumes its block's expected cut time, E[t] = scale / (w + h). On a 6-mark scenario this changed the result from 24 planes, harmony 5, fidelity 83 to 14 planes, harmony 47, fidelity 100.
  • Scenario tests (scenarios.test.js, 13 checks, all passing): wobbly cross plus scribble; box → plane with IoU 0.96; L-shape; diagonal → step; collinear alignment; re-trace merge; correction trade-off; tap pin; determinism; and an interactive budget (6 marks × 200 candidates in about 14 ms).

6. Completion objective

For each candidate partition P:

J(P) = D_harmony(P) + λ(c) · L_fid(P), with λ(c) = 0.3 + 2.7·(1 − c), where c ∈ [0, 1] is the Correction slider.

  • D_harmony: 0.9 × visible-area spread + 0.3 × near-congruent plane pairs + 0.5 × relative density misfit + 0.3 × near-miss jogs.
  • L_fid: Σ over colour regions of (1 − best plane IoU) + 0.25 × generated lines that near-miss a human line.

c also scales the consolidation tolerances (merge τ = (0.15 + 0.30c)·minCell; snap reach = (0.35 + 0.40c)·minCell).

Proposal mixture: odd-numbered candidates also force each region's edges as cuts, so the search space always contains planes that match a region exactly.

Reported Fidelity = mean of (human lines kept), (region IoUs) and (1 − 0.25 × near-misses).

c is a fixed, user-set analogue of the adaptability parameter α in bounded-memory mutual-adaptation models (Nikolaidis et al., 2017). Here the human sets it rather than the system inferring it.

7. Limitations (stated plainly)

  1. Training data is synthetic. Real strokes are used only for evaluation, and only for 3 of the 5 classes. Fill and dot have no Quick, Draw! analogue, so their accuracy is measured on synthetic data only.
  2. Domain mismatch. Quick, Draw! strokes were made in a 20-second guessing game on mouse or touch, not with compositional intent on a canvas. Real Draw & Complete strokes will differ.
  3. Label ambiguity. Some "zigzag" drawings are geometrically indistinguishable from hatching. The remaining 8% zigzag error partly reflects the label, not the model.
  4. Unvalidated metrics. Harmony is a hand-designed heuristic, not a learned or validated aesthetic measure. Fidelity is our own proxy for "it still feels like mine" and has not been validated against human judgement.
  5. Single-stroke only. Gestures are recognised one stroke at a time. A box drawn as 4 strokes works through merging and snapping, not through recognition.
  6. Robot not yet updated. The UR20 runtime still uses the v1 rule (mondrian_generator.snap_marks). It does not yet have this interpreter.

8. Next steps

  1. Collect real data with consent. Log strokes and chip corrections with opt-in consent. Every correction is a free label. Retrain with real data and use uncertainty sampling (chips below 60% confidence are already flagged with "?").
  2. User study (pre-register). Within-subjects, N ≈ 24 non-experts. Conditions: v1 heuristic vs v2 at c = 0.2 vs v2 at c = 0.8, counterbalanced. Each participant completes 3 compositions per condition. - Measures: perceived ownership and agency (Likert, adapted from the Sense of Agency Scale, Tapal et al., 2017); Creativity Support Index (Cherry & Latulipe, 2014); blind aesthetic ratings by a separate panel; number of overrides; time. - Analysis: mixed-effects models with participant as a random effect. - Hypotheses: v2 beats v1 on ownership at equal aesthetic rating; c trades ownership against rated aesthetics. - This study also validates (or refutes) Fidelity as a proxy.
  3. Validate Harmony against Mondrian's own works. Encode public-domain Mondrian compositions as geometry and test whether Harmony ranks them above random partitions. If not, learn the score instead.
  4. Robot parity. Skeletonise the Femto Mega canvas capture into polylines, then run the same interpreter on the Jetson (Node, or a Python port checked against scenarios.test.js).
